# Two existing vendor hosts

This is a procedure, not a passed report. See the [design](../../DESIGN.md) and [evidence format](../../docs/evidence/acceptance-template.md).

Choose two different vendors and open their existing hosts yourself. Record actual versions and tool timeouts. Do not inject hooks, install vendor adapters, change host settings or disable a sandbox. Missing local command/file capability is unverified or incompatible, not universal support.

Use one verified clean-commit candidate and an isolated private data root outside the package. Activate the owner, register a synthetic project and explicitly enable enrollment. Do not give agents owner files, cookies or control capabilities. Create a disposable synthetic Git repository without a remote, with an integration branch and a separate worker worktree. Adopt the managed block only in that explicitly authorized synthetic project.

Give each conversation the same core path, shared skill, private data-root reference and project ID. Use distinct profiles. Pass Windows paths with forward slashes, verify existence, and run version --json and help --json as stateless commands without profile/data flags. Native mutations use UTF-8 without BOM or ASCII JSON Unicode escapes; inspect stored non-ASCII content after the first write.

One agent creates or claims the unique task with N=1 and acts as integrator. It publishes two independent responsibilities, at least one blocked only by a formal human question. The worker joins the same task, claims the independent assignment and starts before the decision if dependencies permit. Do not manufacture a second task.

The user answers on the formal page. Each affected agent rereads the current decision and versions. Workers submit immutable exact base/head and real check/artifact evidence. The integrator reads and reviews deliveries, integrates using the project's own Git tools, runs checks at the exact integrated head, records an integration/candidate and gets the configured acceptance before completing. No push, PR, main-branch merge or release is part of this rehearsal.

Exercise committed-message wait, no-wait retention and resumed conversation. Read the full message before seen; accepted/declined and resolved retain their actual handling/evidence meaning. An ended host is not awakened. End each original session explicitly without releasing accepted historical records.

Preserve real call/output witnesses, exact heads, checks, messages, decision versions and the full integration/acceptance/completion chain outside Git. Compare the original source and final artifacts independently; an agent's report alone does not certify execution. Bind every result to this candidate. See A01/A04/A05/A07/A11/A20/A23/A25 and the other referenced design requirements.
